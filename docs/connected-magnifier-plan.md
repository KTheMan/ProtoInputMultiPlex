# Connected GUI magnifier

Status: bounded independent [acceptance passed](connected-magnifier-assessment-2026-10-14.json). The existing `magnifier` MCP tool now configures, refreshes and exports the GUI-owned user's selected application target. Tool arguments and the 23-tool count are unchanged. The [source review](connected-magnifier-source-review-2026-10-14.json) and [producer](connected-magnifier-rust-checks-2026-10-14.json) cover the implementation; formatting, strict Clippy, 151 tests and x64/i686 builds passed.

| Operation | Current GUI connection authority |
| --- | --- |
| Inspect | Existing enabled connection; metadata only. Inspection remains broader than the permitted-user action set and is not a confidentiality boundary. |
| Configure Off | Session-control grant and an authorized active virtual user. No selected target or capture grant is required to disable magnification. |
| Configure enabled mode | Session control and capture, authorized active virtual user, SelectedTarget source, and a currently selected allowed PID. Desktop capture cannot be enabled through the connection. |
| Refresh | Capture grant, authorized active virtual user, enabled SelectedTarget settings and a currently selected allowed target. Session control is not required. |
| Export | The Refresh authority, a completed cached frame and matching current target HWND/PID and settings/source generation. A newer refresh may be in flight while an unchanged valid frame is exported. |

Use the current acknowledged Agent Access policy. Applying policy revokes existing client IDs; reconnect through the current private descriptor. After Configure, inspect the acknowledged settings before another action. Refresh acknowledges its request while capture runs asynchronously; inspect until the intended user's capture sequence and source identify a completed frame. Use an absolute PNG destination for Export. Success acknowledges a completed file and reports its path and dimensions.

Connected export shares immutable completed pixels with one bounded encoder/writer job. PNG encoding stays in memory until the session rechecks client, policy generation, active stable user, current allowed window and frame generation. Approval is the publication commit point; filesystem work then runs off the routing thread, using an adjacent uniquely created temporary file and atomic replacement. A failure before replacement preserves an existing destination. The pixel-derived PNG budget supports the existing 16-million-pixel viewport limit without returning image bytes through the bridge.

The actor uses a five-second request deadline and retains its busy slot until the worker actually finishes, including after a timeout. Denying or dropping a request before commit performs no filesystem write. Once approved, a timeout or later revocation cannot retract an already authorized publication: the file may still appear even if a successful reply is suppressed. Inspect the destination before retrying. Exact blocked-provider, capacity-collision, large/network-I/O timing and runtime policy/window/settings race behavior have source review, not native acceptance. Worker denial/drop and ordinary atomic replacement have focused unit coverage. Existing local GUI and standalone Export remain synchronous; this group does not establish their I/O responsiveness.

Accepted Configure settings update stored virtual-user seats, Agent profile/nested slots, and the Ouroboros editor. External agent acknowledgements update telemetry without consuming a local pending GUI command. The native gate covered original permitted user A with two owned x64 targets, 24 actual GUI receipts, 15 grouped permission/state/export cases, three product frames and two decoded 96×64 exports, including a deny-delete destination failure. It did not run i686, generated/retired-user native cases, desktop capture, hardware/RustDesk input, general application compatibility or full Ultra/UX parity. All owned processes, handles and test registry resources closed.
