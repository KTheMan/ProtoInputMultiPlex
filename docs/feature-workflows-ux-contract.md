# Feature workflow UX contract

Implementation in the isolated UX checkout. The [delivery record](feature-workflows-ux-delivery.md) and independent review record distinguish accepted workflow evidence, preserved harness failures and remaining measurement limits.

## Output mapping

Output Rules starts with the Home roster user when entered. Changing its user chooser preserves each stable user's settings draft and unfinished key-entry text. Moving to another page does not submit or discard that draft. A clean editor follows acknowledged external output settings; a dirty editor retains its candidate while the committed baseline updates. Appended virtual users do not reset existing drafts. Replacement profiles still reset dependent editors by the established Load/Import/Reset contract.

Apply sends the selected user's candidate to the running worker. Pending commands lock editing; only its matching successful user acknowledgement commits settings. Rejections retain the candidate for correction and retry. Save to profile updates memory while stopped; Save profile is the separate disk persistence step. Discard restores the latest committed baseline for the selected stable user and clears only that user's unfinished editor. An unfinished source/destination key entry must be added to the rules list or discarded before Apply/Save; the controls explain this rather than silently losing the text. Restore legacy mouse output stages the five legacy button rules, preserves existing keyboard rules and clears unfinished key entry; Apply/Save remains explicit.

Existing routing_output MCP operations and grants remain authoritative. External connected acknowledgements update accepted profile state without consuming a dirty GUI draft. This change introduces no public MCP tool, grant, automatic target attachment or default permission. workflow_state is opt-in app-local test instrumentation and emits output draft/committed state and navigation into the existing UI-script evidence directory.

## Profiles

Routine Save/Load remains separate. Load, Import, Restore, Reset and Undo retain their accepted editor replacement behavior. Import/export, profile recovery, automatic targeting scope and backend runtime are closed disclosures so everyday file actions are easy to find. Paths and controls wrap/scroll at supported minimum sizes. All profile file mutations remain disabled while routing; automatic target scope is also read-only until stopped, so accepted session authorization cannot silently diverge from its active profile. The unrestricted-empty-list GUI convention is preserved and is never inherited by MCP. Runtime path edits describe the next session only.

Profile storage remains atomic per file with the existing backup semantics. Undo restores memory only; it does not undo disk writes. Neither this presentation pass nor its tests claims concurrent-writer/crash recovery or whole-product backup.

## Legacy composite automation

The legacy page retains its shared clock, existing authored clip and graph draft, exact worker commands and global Cancel behavior. Named source/target users and grouped secondary controls improve legibility without changing the modern accepted Macro Studio/Graph workflows. Legacy replication changes stay explicit and worker acknowledgements remain authoritative.

## Evidence limits

The companion inventory and independent assessment distinguish source/unit coverage, actual app-local control evidence and reviewed native product pixels. Any supported minimum-size claim requires whole action rectangles and readable status in actual captures, not merely emitted egui shapes. Physical devices, RustDesk input, arbitrary applications, broad DPI/font/screen-reader coverage, same-process independence and complete UX/Ultra parity remain outside this bounded gate unless separately evidenced in the tracker.
