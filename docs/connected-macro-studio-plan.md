# Connected Macro Studio contract

Status: connected authoring/playback and client-attributed recording passed separate bounded virtual assessments: [authoring/playback](connected-macro-studio-assessment-2026-10-14.json) and [recording](connected-macro-recording-assessment-2026-10-15.json). Recording coverage includes six native groups, 14 named outcomes, 28 GUI receipts, three owned frames and two x64 targets; i686 was not executed. The 23-tool MCP surface reuses `macro_studio`; standalone recording and its accepted workflow remain unchanged.

Connected clients may Inspect without a mutation grant. Load, Edit, Generate, Reset, Play, Record Start/Stop and per-user Cancel require the current `session_control` grant and an active virtual user currently permitted by stable identity. Copy/remap checks both source and destination. Play additionally requires the user’s currently selected allowed application target; playback pins the selected window and PID and rechecks current client/user/process authority for delivery. Existing bounded scheduler behavior is reused.

Record Start requires the current session-change grant, an active permitted virtual user, the user's currently selected allowed target, no held input on that selected user, and an idle lane. Holds owned by other users do not block it. Stop is limited to the client that owns the recording and does not require current focus. Only that client's successfully accepted logical virtual actions are captured, exactly once before output conversion; physical/manual/other-client input and replicated copies are excluded. Recording does not prove application consumption. Recorder capacity is preflighted before delivery. An empty or invalid take is discarded while the previous clip and revision remain intact; an error can follow earlier successful batch members or partial native text effects, so inspect recording state before retrying. Disconnect/EOF and that client's connected `ReleaseAll` discard only its working take; local session `ReleaseAll` remains session-wide. Global Stop/Pause/Mode or policy revocation discards active takes. Local GUI Cancel explicitly discards the take without releasing the agent's direct input. Busy lanes reject other authoring/playback mutations, and settings changes that interrupt recording are rejected. Clips remain session-local; Load remaps packet devices and action ownership to the selected virtual lane. No clips enter saved profiles.

A connected Cancel stops only the selected lane when owned by that client. Disconnect cleanup releases that client’s lane ownership; disabling or revoking the global Agent Access policy cancels programs from every connected client. Standalone/local legacy `automation_cancel` retains its explicit session-wide semantics; connected composite mutations remain unavailable.

The GUI treats nested agent states as telemetry and external acknowledgements: committed clip/revision state refreshes without consuming a pending local request or replacing unsubmitted editor fields. The recording view distinguishes the working take from the committed clip; discarding a take does not undo input already delivered to the target.

The recording assessment covers one original recording user, an explicit owner client, a Back output conversion and one graph edge on two virtual x64 targets. It does not cover i686 execution, complete action-family or playback-suite cross-products, general application consumption, physical/global input, hardware, broad delivery rollback, or full UX/Ultra parity. Source/unit tests cover additional capacity, invalid-take and partial-input boundaries not forced by the native gate. The assessment preserves the original raw visual-review status and historical failed aggregates. Legacy composite controls, the replication graph and virtual-replica mutations remain outside this connection slice.
