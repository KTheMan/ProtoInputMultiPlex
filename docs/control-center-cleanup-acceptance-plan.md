# Independent compact control-center gate

Preparation only; launch after frozen images and an exclusive native/GUI slot are supplied. This is a presentation/navigation gate, not another routing feature sweep.

1. **Real Home and compact geometry.** Open an owned 12-seat virtual profile using the product's normal initial page, with no scripted Input Lab/page override. Before the first click, capture only the owned GUI and measure its client extent using its window DPI: approximately 420x600 logical pixels. Resize that owned window to the supported 360x480 client minimum and capture it again. Independently review the quiet Home hierarchy, readable roster, bounded long names, route action and Configure/Settings reachability. Record missing glyphs rather than inferring Unicode readability from bounded width.
2. **Roster and navigation.** Use actual row selection to scroll to the last seat; Configure it, verify the selected identity/name, then Back to home. Reach Settings/Profiles and Tools/Input Lab/Agent Access with actual controls, then return Home. Preserve the complete profile, selected identity where promised, and existing Agent Access grants. If Hide-to-tray appears, require a visible disabled observation; do not test tray lifecycle in this group.
3. **One live two-target session.** Use own x64/x86 probes and virtual device paths only. Start from Home; reach Input Lab through Tools and establish actual F5/F6 DOWN in the two target windows. Return Home and Pause: require actual plain UP messages and both native holds cleared. Resume retains the same worker/target session and navigation state without granting Agent Access. Rehold through Input Lab, return Home and Stop: require actual plain UP, destroyed owned overlays and closed resources.

Keep two finite phases: one DLL-free many-row layout/navigation phase and one native lifecycle/navigation phase. Save original event logs, image hashes, exact image/binary provenance, failed statuses and final cleanup audit. A first delayed real Configure action may provide the initial Home capture interval; it must not change the initial page before the capture. Pixel review is required for the layout judgment; control events or profile telemetry alone do not establish visual cleanliness.

No hardware/RustDesk input, OS input injection, unrelated pixels, profile-feature delivery replay, tray/startup behavior or general MouseMux visual-equivalence claim. Proportional typography, compact structure and reachable controls are the intended bounded visual outcome. Exact observer labels, any existing page/selection snapshot and viewport expansion/return policy must be aligned with the frozen implementation before launch.
