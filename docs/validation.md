## Advanced replication options and queue - bounded virtual acceptance

The `routing_graph` MCP operation supports Inspect/Apply/Cancel and per-edge options for movement, vertical/horizontal wheel, five mouse buttons, anchored/source-relative positioning, virtual-pixel offsets, click delay and temporal step pacing. Missing fields load with anchored, immediate, all-component defaults to preserve older profiles and graph JSON. Candidate validation is atomic. The Ouroboros editor stages and edits the same options and shows route filters/timing in the edge list. The historical graph assessment build exposed 17 tools; adding `virtual_users` produced a historical 18-tool build. Current source exposes 23 tools. The [assessment](advanced-replication-assessment-2026-10-14.json) passed in the bounded virtual scope; the [controls screenshot](advanced-replication-control-center.png) and [visible overflow warning](advanced-replication-overflow.png) show the tested workflows.

Positioning and timing compose hop-by-hop. Source-relative edges place the destination from the processed source position plus offset; anchored edges keep the existing destination anchor while forwarding incoming displacement. When multiple paths reach a user, the deterministic canonical path uses stable seat-ID order, independent of edge order, and each component is emitted once. Click delay preserves ordered down/up behavior. Step interval spaces later events after an immediate first discrete event; paced motion coalesces toward the latest goal and ends with a final snap barrier. Relative positioning was verified for motion; automatic button repositioning is not claimed. Compound mouse packets remain unsupported by inherited packet validation; per-component filtering inside such a packet is not claimed.

The scheduler caps combined event/motion jobs at 4096, uses estimated pending-payload accounting capped at 8 MiB, and separately bounds active cadence reservations at 4096. The native gate exercised the actual 4096 event-count cap: an excess source-down is rejected before source-target dispatch, queued copies are cancelled, replication suspends, ordinary input continues uncopied, and source-release cleanup is delivered. Byte-only overflow and cadence-reservation exhaustion have portable source/unit coverage; neither cap was exercised natively. The GUI control **Cancel pending replication** and MCP `routing_graph` cancel operation clear scheduled copies and replication-owned holds while preserving ordinary/source-program ownership, graph definition and revision. A valid Apply resumes queue state; separate native delivery after recovery was not verified. A source-program failure releases only that program's claims. Existing pause, stop and stdio EOF retain session-level release behavior.
