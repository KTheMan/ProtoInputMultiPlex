# Roadmap toward independent desktop input

The October 15 delivery slice adds Rust installation transactions,
data-preserving upgrades/uninstall, retained-release rollback, and versioned
whole-data migration/backup/restore. See [Installation and recovery](installation-recovery.md)
and its separate current-distribution verification/independent acceptance records.
Actual logon/reboot, signing, hardware and general reliability work remain open.

The target is **MouseMux Ultra functional parity** with an independently implemented familiar UI. The [parity matrix](ultra-parity.md) defines product scope and records evidence; the priority order below controls remaining work.

## Current priority order — October 14, 2026

Optimize for reliable agent use and two users sharing a Windows desktop. Multi-user app/browser integrations are second-lowest priority; pen, touch, touchpad and gamepad adapters are lowest. These remain in the full parity target.

MouseMux's [edition comparison](https://www.mousemux.com/pricing/), reviewed October 14, places ordinary mouse/keyboard use, personalization, magnification and profiles in the Free/Core foundation; Advanced adds locks, drawing and tuning, while Ultra adds macros/replication, GPU cursors and broader remote use. That informs the order, but agent workflows and the user's explicit deferrals take precedence. Do not reproduce license gates, seat caps or session timers.

### Execution rules

- The bounded lifecycle baseline is accepted; continue the remaining P1 reliability work while selecting the highest unfinished priority with satisfied dependencies. Within it, prefer work that unlocks both agent and two-user workflows.
- Add relevant Ouroboros controls, MCP support and skill guidance with each feature. P2 closes shared agent-workflow gaps; it is not a reason to postpone agent support elsewhere.
- Each group needs concrete acceptance criteria and independent approval before it is marked complete. Preserve accepted evidence and failed aggregates; test missing criteria and meaningful regressions rather than repeatedly replaying whole families. Run the required Rust checks for Rust changes.
- Use only virtual devices and disposable, explicitly selected applications. This order does not authorize hardware or RustDesk-mouse testing. Physical-device, broad desktop and same-process isolation claims require their own evidence and remain unverified where that evidence is absent.
- Priority changes do not change implementation or acceptance status. The [parity matrix](ultra-parity.md) and [validation record](validation.md) remain the evidence indexes.
