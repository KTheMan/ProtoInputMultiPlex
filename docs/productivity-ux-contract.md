# Utility-page hierarchy and attachment status contract

This is one bounded UX slice for the three utility pages: Virtual Replicas, Macro Studio, and Replication Graph. The intent is to put the action a user came to perform first, keep current status and errors visible, and move implementation detail behind deliberate, default-closed Ouroboros disclosures. The page reorganization retains existing action labels, script observers, recipient selection, revision checks, validation, and pending guards. State-relevant controls replace competing disabled action rows; separate attachment telemetry reports the backend setup result. It adds no public MCP tool or request schema.

On Virtual Replicas, start/stop and the source/target selection remain the primary controls. `Route options` contains the existing per-edge options; `Stable identity details` exposes full stable seat and source IDs without repeating them in every roster row. The active/tombstoned roster, operation status, and errors stay visible without opening either disclosure.

On Macro Studio, state-relevant recording and playback controls come first: Start and subdued Play while idle, local Stop during local recording, Discard during agent recording, and Cancel during playback. `Clip files` groups save/load, while `Timeline and edits`, `Pattern and jiggle`, and `Playback options` group the existing event authoring, generator, and timing controls. Current recording/playback state and actionable errors remain outside those details. Per-user ownership, pending-command guards, and clip/revision synchronization are unchanged.

On Replication Graph, `Connect users` and the existing edge/category controls remain the primary path. `Advanced edge behavior`, `Connections`, and `Graph tools` contain the existing edge configuration, graph list, and file/history tools. Endpoint availability is evaluated outside the disclosure after current-frame endpoint edits, so closing it does not disable valid connection actions. Blocking staged-option errors stay outside the disclosure. Apply still validates the complete staged graph and uses the existing explicit revision/pending guards; this layout change adds no rollback or stronger atomicity guarantee. Applied revision, unresolved-endpoint warnings, suspension/queue state, and errors remain visible outside the detail sections.

The GUI also reports lazy automatic-desktop target attachment as a separate status. A new backend open emits `Attaching(pid)` followed by `AttachmentFinished { pid, error }`; completion follows either result of the backend `open` call. Only a matching in-flight PID clears progress. Success does not replace the global command result, page errors, or pending acknowledgements; failure has its own visible notice and full hover detail. The router preserves its per-user routing error. Failed PIDs are cached for the session, so recovery uses the existing stop/restart path. Script status reflects the displayed attachment notice alongside the existing command result.

This attachment status describes the backend setup call only. It does not establish that the target consumed an input event or that a failed open left no partial native setup. Failed-open notification and mismatched completion have synthetic-event unit coverage. Real failed-open races and overlap with page-owned pending operations have no native acceptance claim.

Initial utility-page sizes are Macro Studio 760×620, Replication Graph 860×680, and Virtual Replicas 760×620. Navigation selects a size once; manual resizing remains respected. The wider forms remain scrollable. Required producer checks are formatting, strict workspace Clippy, workspace tests, and both Windows builds. Independent [bounded acceptance](productivity-ux-assessment-2026-10-15.json) passed representative normal/minimum views, real virtual clone Start/Select/Stop and agent-recording Discard. Seven accepted originals retain their separate build provenance; previous failed aggregates and visual rejections remain unchanged. This does not establish full Ultra/UI parity.

The [final producer](productivity-ux-rust-checks-2026-10-15.json) passed formatting, strict Clippy, 185 workspace tests and both Windows builds. i686 was built but not executed. Minimum replica identities are readable across separate vertical views, while the minimum Graph frame establishes error visibility rather than whole Apply visibility. Full hover/accessibility interaction, broader font/display coverage, physical devices and arbitrary applications remain outside this gate.
