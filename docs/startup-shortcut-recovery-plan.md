# Recover saved shortcuts without losing the settings UI

Initial shortcut registration currently fails before the GUI is created. An occupied saved chord can therefore prevent opening Preferences to repair it. This P1 group keeps the lifecycle window and tray alive after initial shortcut registration fails, leaves the whole shortcut set inactive, and opens the normal visible GUI even when Launch minimized is saved. Routing remains unavailable until the complete saved set is activated by explicit Retry or a successfully committed preference edit. Saved preferences are never silently rewritten.

Keep transactional staging, accepted-only dispatch, shared emergency Stop ownership, explicit target selection and normal cleanup. Failed Retry and failed/cancelled preference edits preserve the inactive state. Revert changes only the draft. An intentionally empty successfully accepted shortcut set is permitted by existing policy. No automatic retries or automatic routing.

The Home recovery row and Application preferences use Ouroboros controls. Connected `app_preferences` projects live shortcut status through the existing permission boundary; standalone documents report null health because a file write does not activate another process. A freshly inactive GUI has no live Agent Access session, so this group does not add remote correction of that stopped GUI. Window creation and tray installation errors remain fatal; real logon/reboot, malformed preference-file recovery and full P1 reliability remain open.

Acceptance uses owned foreign registrations, app-local egui events and disposable targets only. Check a saved custom chord conflict after a successful default registration (no partial registrations), failed Retry, release of the owned conflict, successful Retry and one no-input Start/Stop. Separately check a default-chord conflict after a custom registration, Revert and unchanged Apply rejection, then a corrected complete saved policy. Verify visible startup despite Launch minimized, disabled Start, unchanged disk until successful Apply, compact complete controls, process/overlay cleanup and no hardware/RustDesk input. Root runs one frozen Rust producer with required checks and both builds. An independent reviewer must approve source, harness, observed data and relevant pixels before this group is called complete. Preserve failures and test only missing acceptance criteria if repair is required.
