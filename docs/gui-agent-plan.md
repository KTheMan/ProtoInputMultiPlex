# Live GUI agent connection

The optional GUI connection lets an MCP client use the active Ouroboros routing session. Its bounded virtual GUI/native gate passed; see the [independent assessment](gui-agents-assessment-2026-10-14.json) and [Agent Access capture](gui-agents-control-center.png). This document records that tested scope, not general desktop access or broad application compatibility.

Current connected extensions have separate contracts and assessments in [the agent guide](agents.md), including [Macro Studio recording](connected-macro-recording-contract.md), [magnifier](connected-magnifier-plan.md) [stable-ID graph editing](connected-graph-contract.md) and [virtual-user lifecycle](connected-virtual-users-contract.md). The original connection slice below describes its historical 20-tool build.

## Workflow and permissions

1. Start a normal GUI routing session and open **Agent Access**.
2. Select active virtual users and eligible target PIDs. The page does not widen the routing policy. An empty PID list in automatic GUI routing keeps the existing unrestricted policy, but agents still act only on an explicitly selected eligible target. Assigned-process candidates come from the profile's existing targets.
3. Enable agent access to create the protected local connection descriptor. Start the MCP server with `mcp --gui-connection <descriptor.json>`.
4. Enable target capture or session-level changes separately if required. Both are disabled by default. Capture is limited to an explicitly selected permitted target window. Session-level changes support cursor settings, output configuration, mode, pause and resume. `routing_output` Inspect remains read-only; Configure requires the existing explicit session-level permission plus the same permitted-active-user and authorized-PID checks as other live mutations. Mode changes are available only for automatic desktop routing and require the permission policy to include every active user. Pause and mode operations are global and may release GUI-owned programs and held input.
5. Disconnecting or stopping the MCP client releases that client's owned input and disconnects it; it does not stop GUI routing. `release_all` is scoped to the requesting agent's ownership. Disabling access or stopping the GUI session closes the broker.

Standalone `mcp --runtime <directory>` remains the separate-session workflow. Unsupported live mutations return an explicit unavailable-operation error in GUI-connected mode; standalone tool behavior is unchanged. In the historical 20-tool connection slice, connected Macro Studio, annotation, magnifier, graph and virtual-replica mutations were unavailable. The current extension contracts linked above supersede those operation limits; connected virtual-replica mutations now have the separate scope contract linked above.

## Scope and resource limits

The connection uses a local named pipe protected by the current logon SID and a private descriptor. Do not publish or log descriptor contents. Transport permits up to eight concurrent clients; the Agent Access user selection is an independent seat-level policy. Requests and idle connections have 50-second deadlines. One broker is owned by the GUI controller session and is removed on disable or session stop.

Capture is opt-in and runs single-flight on the routing worker. A frame is limited to 16 megapixels and a 2 MiB PNG, with a five-second response deadline. The assessment decoded an actual 3979x3986 client image (15,860,294 pixels, 321,034-byte PNG) and a smaller PNG from owned cooperative targets; another target seat delivered its native F9 key while the large capture/reply was outstanding; that input took 47 ms and the capture/reply took 5.109 seconds. That is a fixture measurement, not a general latency guarantee. Provider-hang timeout retention was not exercised. The result is a PNG and metadata for the selected target window, not an unrestricted desktop screenshot. A target must be selected and permitted before capture. The PID policy authorizes native focus, capture and click/gesture input; it does not confine the virtual cursor to a window rectangle. Unfocused movement may position a cursor, while click targeting is checked against the PID policy. GUI recorders do not include input submitted by connected agents.

Input and capture operate on known, explicitly owned virtual-session targets. They do not move the OS pointer, observe physical input, read arbitrary desktop pixels, or establish physical-device, same-process isolation, desktop-wide isolation, or arbitrary-application compatibility.

## Bounded acceptance and remaining limits

The independent assessment passed six substantive evidence groups and 37 actual GUI control occurrences across 21 labels on one x64 GUI-owned automatic-routing session. It exercised three original seats and four explicitly owned cooperative x64/x86 target applications. The gate verified the actual SID-protected descriptor and pipe, authenticated clients, actor-scoped key release/disconnect, target PID policy, capture permission and decoded source pixels, disable/stop cleanup, and granted settings/mode/pause/resume changes. See the [full assessment](gui-agents-assessment-2026-10-14.json) for scope and preserved earlier artifacts marked NOT ACCEPTED.

The gate discovered the current 20-tool MCP surface and used an x64 GUI/controller only. It did not exercise an x86 controller, assigned-process GUI-agent mode, arbitrary application capture, forced provider hangs/timeouts, cross-logon or remote clients, client-capacity overload, crash-time descriptor deletion, delayed graph changes, alternate actors with queued macro programs, or complete same-process isolation. It does not establish physical-device behavior, broad app compatibility or full Ultra parity. Successful product Disable/Stop cleanup was observed; runner cleanup after a failed run is not product behavior. Producer checks are separate and recorded in `gui-agents-rust-checks-2026-10-14.json` (formatting, strict Clippy, 95 workspace tests and x64/i686 builds).
