# Conditional vertical-to-horizontal scrolling

The cursor settings now include `horizontal_wheel_emulation`: `never` (the backwards-compatible default), `always`, or `while_primary`, `while_secondary`, `while_middle`, `while_back`, and `while_forward`. It converts vertical wheel input into horizontal output according to the raw source button currently held for that user. The trigger remains the incoming source button even when its output is disabled or mapped to a key. This is separate from `horizontal_wheel`, which handles input that is already horizontal: ignore it, convert it to vertical, or preserve it. Horizontal output scale and inversion are independent of the incoming-packet policy and are applied once to the output.

Ouroboros exposes the setting on the Wheel page and stages it with the existing cursor settings Apply workflow. It is available only for virtual mice in automatic desktop routing or concurrent assigned routing. Unsupported routes show the retained setting as unavailable and do not silently clear it. Existing profiles omit the field and keep `never` behavior. MCP uses the complete `routing_settings` object; there is no additional tool.

The independent [bounded virtual assessment](conditional-wheel-assessment-2026-10-14.json) passed five native behavior groups, 26 automatic UI clicks, a 17-click assigned prefix plus an 11-click cleanup tail, and physical/fixed-mode unavailable checks. The initial native prefix, assigned UI prefix and offline UI prefix retain their original NOT ACCEPTED aggregate results; accepted subgroups and corrected tails remain separately identified. All five raw triggers were sampled on x64, with representative conversion math, origin and queued-delivery cases on x86, not a full architecture-by-option cross-product. The UI screenshot shows the actual seven-option dropdown and selected While Back state ([control-center image](conditional-wheel-control-center.png)). The current source passed formatting, strict Clippy, 121 workspace tests and x64/i686 builds ([producer record](conditional-wheel-rust-checks-2026-10-14.json)); its 22-tool MCP schema was inspected.

The accepted scope uses owned virtual devices and disposable applications/files only. It does not establish hardware wheel behavior, arbitrary-application scrolling, same-process isolation, broad Ultra parity, forced native API failure, filtered message-pump cleanup or a direct-router fallback. Synthetic offline PIDs were never attached; physical unavailability used an unresolved fixture path. The initial offline frame stall is retained and is not claimed fixed by product code. See the public [MouseMux manual](https://www.mousemux.com/pages/manual/) for the high-level vertical-to-horizontal workflow that informed this feature.
