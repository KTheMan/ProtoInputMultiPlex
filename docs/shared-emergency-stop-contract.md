# Shared emergency stop

The Rust implementation and bounded virtual/native/GUI acceptance are complete for the scope below. Broader P1 reliability, full Ultra parity and full UX parity remain open. See the [canonical assessment](shared-emergency-stop-assessment-2026-10-15.json).

The default Ctrl+Alt+Shift+F11 Stop shortcut uses one hidden Rust helper shared by controllers using the same executable path, metadata and version on the same Windows logon and desktop. A successful subscription confirms that helper owns the Windows hotkey registration. Supervised standalone MCP automatic-desktop/concurrent routing acquires its lease before worker spawn; direct CLI attach and nonconcurrent assigned sessions retain their existing behavior. The GUI subscribes only while accepted preferences enable the default Stop binding. An unrelated owner prevents acquisition. The helper has no routing, input-injection or capture authority.

Each standalone MCP desktop session using supervised automatic-desktop or concurrent routing holds its own pipe lease. The GUI holds a lease only while accepted application preferences enable the default Stop shortcut; custom or empty shortcut policy may omit it. A default emergency event stops all participating sessions through their existing cleanup paths. A GUI Stop button, MCP `routing_stop`, or standalone EOF still affects its own session. It does not stop peers. A helper survives the first subscriber leaving and exits after the last lease closes. Abrupt subscriber exits are pruned through retained process identities and pipe disconnection.

The endpoint has a protected current-logon DACL and rejects remote pipe clients. Both ends check the peer process, creation identity, and the same executable path, metadata and version. Sharing is limited to participants on the same Windows logon and desktop; a different path or build is not covered. Versioned messages carry broker timestamps and monotonic stop generations. Reads, writes, admission and connection attempts are bounded. Established subscriptions never reconnect automatically. Process death, lost connection, stale heartbeat or malformed traffic makes that subscription fail closed and requests ordinary Stop. Cleanup failure retains the existing quarantine rules; a safety notification alone is not proof of clean retirement.

The GUI shows unavailable emergency coverage, disables Start and offers **Retry emergency stop** after routing stops. Retry explicitly obtains a new healthy subscription. An accepted preference change that removes or replaces the shared default binding may also restore coverage by policy. Start performs another health check. Preference changes retain the existing stage/commit/rollback behavior; the default chord is reserved for Stop, other custom chords remain exclusively registered, and an explicitly committed policy change can remove the shared subscription. A pending preference transaction blocks Retry.

MCP exposes a lost-coverage reason through the existing `routing_state.last_error`. No MCP tool or permission is added. Agents must inspect running/recovery state after this notification and must not replay interrupted input. Target PID scope, client grants, input ownership and capture permissions remain unchanged.

Bounded acceptance covered standalone MCP desktop sessions sharing the helper and GUI participation in separate native/GUI workflows. Native runtime evidence verified per-session isolation when standalone `routing_stop` or EOF stopped one session while another remained active, plus all-subscriber emergency fanout and last-lease shutdown. GUI evidence separately verified broker-loss cleanup and the solo Retry/Start/Stop workflow. Source behavior keeps ordinary GUI Stop local to its session; that GUI-plus-peer combination was not directly tested. The GUI broker-loss functional prefix retains its NOT ACCEPTED aggregate; independently accepted subgroups and separate retry/layout tails are not relabeled as a passing aggregate. Producer provenance, phase counts, retained verdicts and detailed limits are in the [validation record](validation.md#shared-emergency-stop--october-15) and [canonical assessment](shared-emergency-stop-assessment-2026-10-15.json). Tests used virtual input and disposable targets under an x64 controller; i686 was built but not run. The two final GUI originals are 360×360 and 320×360, but the Home footer status remains cropped. Hardware key activation, mixed executable paths/versions, other desktops/logons, arbitrary application compatibility and full P1/Ultra/UX remain outside this gate.
