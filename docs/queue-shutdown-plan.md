# Virtual input queue shutdown

The Rust backend has a version 3 queue-fence adapter. The [independent Output Rules assessment](output-rules-assessment-2026-10-14.json) passed bounded virtual Stop behavior for ordinary message pumps and tested timeout reporting; this remains queue-level cleanup evidence, not proof that an application consumed or acted on input.

At shutdown, Rust freezes generated input, stops the focus loop, disables generated message delivery, and hides the fake cursor. It then posts a fence to each tracked target GUI thread after the route's already-submitted release packets. A process watch prevents PID reuse; the target HWND must still belong to the expected process and GUI thread. The target's GetMessage hook or a PeekMessage call using PM_REMOVE acknowledges the fence and masks its private registered message as WM_NULL. PM_NOREMOVE masks only the returned copy; it neither acknowledges nor removes the queued fence. The shared deadline is bounded, and Rust waits for either the target event or process exit.

The loader export returns false only before it attempts pipe transfer. Once transfer may have started, it returns true and Rust treats the remote event handle as target-owned. The target closes a registered event after acknowledgement, on a failed post, or during target process teardown. Rust never cross-closes a possibly live remote event after a timeout. A failed acknowledgement reports shutdown failure; worker supervision remains responsible for its own stop deadline.

This only covers ordinary, unfiltered message pumps that retrieve the posted marker. A window-specific or message-range PeekMessage call can leave the marker queued while retrieving other selected messages. Conversely, PM_REMOVE for the fence's range can retrieve it before an earlier key-up. A fence receipt therefore does not prove that all earlier releases were normalized under filtered retrieval; that behavior remains outside the accepted shutdown guarantee. PM_NOREMOVE does not count. A process that does not pump messages may time out. The mechanism does not guarantee delivery to application code, clear arbitrary application queues, or prove that every message family has been consumed. If a pipe closes with fences outstanding, the injected message-filter hook remains installed so a late ordinary pump can still acknowledge; restart the target after a timeout or unexpected controller exit.

The native bridge is isolated in [the queue-fence delta](../patches/queue-fence/0002-queue-fence.patch), with the [original patch](../patches/archive/0001-backend-before-queue-fence.patch) and [compatibility record](queue-fence-compatibility-2026-10-14.json) preserved. The top-level compatibility patch includes the delta so existing idempotent build checks remain valid. Target event ownership follows [DuplicateHandle](https://learn.microsoft.com/en-us/windows/win32/api/handleapi/nf-handleapi-duplicatehandle); queue removal follows [PeekMessage](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-peekmessagew).

The assessment covers seven native groups, a corrected nine-control Stop supplement, two timeouts, connected actor boundaries, and offline controls. Its original 35-control UI artifact records PASS, but only 34 feature controls are accepted because the old plain-Up Stop behavior failed; the new Stop supplement proves normal delivery after the v3 repair. A 27-control connected prefix retains its NOT ACCEPTED aggregate, with a separate 20-control tail; five offline controls and the timeout cases complete the acceptance basis. These are artifact control-step occurrences, not distinct control counts. The two tested timeout cases report failure after about 1.03 seconds without a pumping thread and 1.14 seconds with PM_NOREMOVE polling; a late plain Up is normalized after ordinary pumping resumes, but safe session reattachment was not tested. Earlier NOT ACCEPTED native, decoder and connected records remain unchanged. See the [full conversion contract](input-conversion-plan.md), [decoder checks](output-rules-decoder-source-checks-2026-10-14.json) and [producer record](output-rules-rust-checks-2026-10-14.json). Selected-range PM_REMOVE may overtake an earlier Up; filtered pumps remain outside the accepted shutdown guarantee.
