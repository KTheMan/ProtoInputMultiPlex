# Per-user Pause/Resume

Native acceptance covers concurrent automatic virtual routing, including the November 6 shared checkout with the default Rust worker. Assigned routing and failure injection have source and unit coverage. Pause state lasts for the session. [Original assessment](per-user-pause-assessment-2026-10-29.json) · [Integration assessment](rust-port-feature-integration-2026-11-06.json)

The first supported scope is ordinary independent routing with virtual mouse/keyboard pairs in concurrent automatic desktop mode with independent keyboards, or concurrent assigned mode. Switched mode and shared-keyboard routing are visibly unavailable for this group. Pausing a user preserves that user's target selection, attachment and process reservation. It discards only that user's queued motion and releases that user's saved native holds. Other users retain their holds, queued motion and independent programs.

Pause takes effect before release attempts. Failed releases retain their original recipient and remain visible as cleanup pending, with scoped retries. Resume is unavailable until cleanup succeeds or the original process exit is established, and while the whole session is paused. Global Resume leaves individually paused users paused. Resume does not publish old motion or replay input.

The worker tracks admitted external DOWN identities independently of delivered native holds. Pausing quarantines that user's held sources across manual and connected clients. Paused input is discarded before recording, graph processing or delivery. Repeated DOWN remains suppressed after Resume until that actor sends its matching UP; the next fresh DOWN may route normally. Client EOF retires only that client's source markers, while failed native-release receipts remain retryable. Source grants remain required for a connected client's UP; a denied UP has no effects and leaves the marker intact until authorization is restored or the client retires.

Controls must show unsupported combinations before dispatch. Active mapper paths, replication, forwarding, synchronized composite work or an affected independent program/recording must be stopped or removed before pausing the affected user. Starting affected automation while a user is paused must also fail before mutation. An unrelated user's independent program remains usable. Physical hooks and fixed-relative routing are outside this first group.

The Ouroboros selected-user control uses worker state and a private request/identity acknowledgement. Periodic or connected-client events can update displayed state but cannot acknowledge a pending local request. New sessions, Stop and profile changes retire pending requests. MCP adds `pause_user` and `resume_user` actions to the existing `routing_input` tool; global Pause/Resume remain available. Mutation requires session control and grants for the affected user and selected target, and clients cannot supply private GUI acknowledgement tags.

The bounded native acceptance covers two virtual users in two separately owned target processes: retained B holds and continued typing/motion while A is paused; suppressed A input from multiple actors; no stale repeat after Resume; a real source UP followed by fresh A input; global pause precedence; denied permissions with no effects; normal and minimum-size controls; and normal Stop/Quit. Focused tests cover failed release retry, queued-motion isolation, source quarantine across global cancellation, client EOF isolation and mapper readiness. Native fixed-relative, real devices, same-process isolation, arbitrary applications, the historical GUI stall and full Ultra parity remain open.
