# Annotation PNG workflow

Close the missing connected annotation export capability and make the same workflow asynchronous for local GUI and standalone callers. Keep original Rust/Ouroboros controls, existing tools and default-off grants. P1 tray initialization remains a documented fatal startup boundary; this group advances the missing user/agent drawing capability and does not close P1 or full Ultra parity.

Add `ink_scope: selected_user | all_users` to Export. Omission retains the historical all-user ink canvas. Selected-user rendering filters strokes while preserving straight alpha, clipping and paint order. Ink is a bounded snapshot at request revision; later drawing does not mutate that snapshot. Transparent export contains logical ink only. Composition captures the exact selected client window, then composites the selected ink scope; it never reads desktop pixels.

Connected PNG exports require the existing capture grant, an authorized active virtual user, and every active user for all-user ink. They do not need the session-change grant. Configure/Clear permission semantics stay unchanged. Composition additionally requires the selected PID in current Agent Access permissions. Retain the original process handle and recheck process liveness, stable user identities, policy generation, selected HWND/PID and physical client bounds before publication. All-user roster changes invalidate approval. Local GUI/standalone use the same jobs without acquiring agent grants.

Capture, rasterization, PNG encoding and filesystem work run off the input thread. One annotation job per routing worker remains occupied through timeout, disconnect, revocation or denied commit until preparation actually finishes. No file is created before explicit authorization. Publication atomically replaces its requested destination with bounded temporary-file cleanup. Approval is the commit point; revocation after approval cannot undo an authorized file. A timeout after approval must tell callers to inspect the destination before another export. Stop/crash after approval can terminate the writer: file completion and temporary cleanup are indeterminate at process termination, not guaranteed across exit. Pending/completion telemetry cannot acknowledge a different GUI command or client sequence. Stop before approval drops permission.

Add Ouroboros selected/all-user ink controls, clear pending state and concise completion status; explain the existing capture grant on Agent Access. Preserve previous kind selectors and unrelated forms. MCP and installed agent guidance must distinguish snapshot revision, permission, completion, file existence and actual target delivery.

Acceptance uses only virtual users and owned disposable targets. Decode selected-user/all-user transparent pixels and selected-target composition; check permission denial without output/temporary files, original file preservation on a publication failure, and explicit GUI export controls. Use the existing owned capture-delay fixture to verify another user's input continues during preparation and policy revocation before commit denies publication. Sample timeout retention and stopped-owner cancellation with bounded tests where practical; do not claim untested provider/OS failure coverage. Generalizing the PNG worker needs one focused magnifier export regression, not replay of the accepted magnifier family. Required Rust checks and both builds precede native runs. An independent agent reviews source, harness, native data and relevant pixels before acceptance; preserve failures and cover only missing criteria after a repair.
