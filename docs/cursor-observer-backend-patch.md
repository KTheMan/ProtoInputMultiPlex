# Optional application cursor observer bridge

Source implementation pending native build and independent acceptance. This document does not establish application or Ultra parity.

The pinned ProtoInput compatibility delta is isolated in [0003-cursor-observer.patch](../patches/cursor-observer/0003-cursor-observer.patch). The exact preceding consolidated patch is preserved in [0001-backend-before-cursor-observer.patch](../patches/archive/0001-backend-before-cursor-observer.patch), SHA-256 `593f292c840edeb8fa388972be00c95216a62eb8cfa05c86df2963dcb56c0007`. The top-level [0001-backend.patch](../patches/0001-backend.patch) includes the new delta so the existing build script's idempotent checks remain applicable. Both the isolated delta and consolidated patch passed `git apply --reverse --check` against the current vendor worktree. Existing queue-fence and unrelated compatibility changes remain present.

The C++ delta adds optional cdecl loader exports `MuxCursorObserverVersion` (1), `MuxCursorObserverStart`, `MuxCursorObserverAssociate`, and `MuxCursorObserverStop`, and three fixed-width pipe packets appended after the existing message IDs. Start forwards mapping/mutex handles duplicated into an already attached target; Associate forwards a PID-validated HWND and selection generation. Complete frames share the existing loader pipe write mutex. A false Start result guarantees no pipe write began; once writing begins, the loader returns true even after a partial write because the target may already own the handles. The host never cross-closes handles after that transfer. This bounds ambiguity to one mapping per target until Stop acknowledgement or process exit.

The target bridge resolves five Rust observer exports from an absolute DLL path beside the injected Hooks DLL: `protoinputmultiplex_cursor_observer64.dll` or `protoinputmultiplex_cursor_observer32.dll`. Restricted dependency search is used. It retains the loaded module until target exit so a hook cannot call unloaded code. An unavailable observer closes received Start handles. Rust Start consumes both handles on every result. All five Rust callbacks return an integer result code: 0 succeeds, 1 is disabled, 2 is busy, 3 is invalid, and 4 is capture failure. The C++ bridge records an active attachment only on Start result 0, and clears it only on Stop result 0; an unsuccessful Stop retains its attachment for EOF cleanup. Associate, Notify and Motion do not interpret callback results as booleans or change attachment ownership. The three existing cursor hooks forward only their target-local cursor/visibility and selected HWND. After its existing virtual WM_MOUSEMOVE post, RawInput forwards the selected HWND to the optional Rust `ProtoMuxCursorObserverMotion` export. Rust checks the current explicit association and asks that target window to process WM_SETCURSOR, enabling ordinary Win32 class/control cursor behavior without querying the interactive desktop cursor. SetCursor forwards non-null visibility directly, independent of the legacy FakeCursor visibility toggle, so a non-null cursor can become visible again after SetCursor(NULL). ShowCursor reads the existing FakeCursor handle through a small accessor and forwards its immediate boolean event; this does not model the full original API display counter. pipe EOF invokes Stop before existing native hook cleanup. No host desktop cursor query or global pointer action is added.

All cursor capture, copied-image ownership, thread/window association, bounded conversion, status publication and shutdown acknowledgement belong to the Rust observer. Its fixed 112-byte header and at most 256×256 premultiplied BGRA payload contain no foreign object handles. The host `app_cursor` module creates unnamed mapping/mutex objects, verifies the original process watch remains alive around duplication, reads coherently with zero-timeout mutex acquisition, and validates PID, attachment, HWND, association, sequence, dimensions, hotspot and premultiplied pixels. It invalidates old-selection observations immediately. Identical image content has a stable image identity independent of notification sequence. Provider errors remain per-target fallback observations and do not fail input routing. A selection that has not produced a usable snapshot after two seconds reports that fact while keeping the configured cursor. It does not retry mapping setup or imply that observation became active. Explicit disable clears a failed-setup status so later opt-in may retry only after the previous mapping is safely stopped.

The host keeps a disabled mapping until the Rust observer publishes `STATUS_STOPPED`, or until the original process exits. It does not start another mapping for the same live target while Stop remains unacknowledged. During shutdown it queues Stop before the existing input fences and reverse hook removal. Dropping host references is safe because target mapped views and duplicated handles retain their own kernel object lifetime. A failed or partial command transfer can leave target handles alive until target exit; it must never trigger unsafe remote-handle closure or a repeated mapping setup.

These source checks do not prove compilation, loading, cursor pixels, cleanup timing, arbitrary application support, same-process multi-user isolation, physical device behavior or mixed-DPI correctness. Those require the separate bounded feature acceptance gate.
