# Extended cursor appearance controls

The appearance model now supports cursor size through 256 pixels, user-name label placement and font size, independent short-badge shape and placement, and optional idle hiding. The Ouroboros Theme and Overlay pages stage these settings with the existing cursor-settings Apply flow. The preview scales large cursor glyphs to fit while showing label and badge placement. Idle hiding affects the overlay only and remains suspended during an active mouse hold. GDI dimensions are current-desktop coordinates; mixed-DPI behavior remains unverified.

Extended controls are available for automatic desktop routing and concurrent assigned routing. Fixed routes show the saved values as unavailable and reject non-default extended-overlay settings before mutation. Profile preview and discovery remain usable without ProtoInput DLLs. `routing_settings` exposes the fields through its existing full-replacement object; no MCP tool was added. The bounded virtual gate passed: four native groups, 16 rendered variants plus one x86-owner pixel sample, and 44 actual GUI click occurrences plus six disabled-control observations. The [independent assessment](cursor-appearance-assessment-2026-10-14.json) and [evidence manifest](cursor-appearance-evidence-manifest-2026-10-14.json) preserve exact scope and hashes. Eight earlier aggregate artifacts remain NOT ACCEPTED. Corrected producer checks passed formatting, strict Clippy, 125 workspace tests and x64/i686 builds; see [producer checks](cursor-appearance-rust-checks-2026-10-14.json). The earlier [initial checks](cursor-appearance-initial-producer-checks-2026-10-14.json) predate cached-DIB print support.

The additive settings are `label_position` (`right`, `left`, `above`, `below`), `label_font_size` (8–48, shared with badge text), `badge_shape` (`rounded`, `box`, `circle`), `badge_position` (`inline` or the four corners), and `idle_hide_ms` (`null` or 250–600000). Existing profiles retain Right, 14-pixel text, Rounded/Inline badges and no idle timeout. The native canvas is measured and capped at 1024×1024. Labels use at most 64 Unicode scalars including an ellipsis and 512 measured pixels; the combined cursor/badge budget can truncate them further. Name cache work inspects only the first 65 raw scalars, and position-only changes reuse the rendered bitmap. Badges retain the existing eight-scalar input cap and can be shown without the name label.

Authorized raw mouse packets refresh only their user's activity before output filtering, including disabled and key-remapped buttons. Replay, replicas and `MoveTo` use the supervised route; keyboard/text packets do not wake another pointer. Monotonic idle time affects visibility only, with an actual held mouse/drag keeping the cursor visible. Valid settings reset the selected timer; Pause and Resume do not continually refresh it. Saved `visible: false` remains hidden after activity. State exposes `idle_hidden`, canvas dimensions, hotspot, bounded rendered text and paint generation. Connected-agent activity forwarding has source/unit coverage, but independent native connected-agent wake behavior is untested; this group's native gate does not replay the entire Agent Access suite.

The gate exercised actual dropdown options, font and size controls, badge independence/shape/placement, idle timeout and mouse-held visibility, Apply plus stopped profile roundtrip, fixed-mode disabled observations and no-mutation rejection, and owned-window pixels from the cached overlay DIB. See the [control-center capture](cursor-appearance-control-center.png) and [owned-pixel archive](cursor-appearance-owned-pixels-2026-10-14.zip). Long-name layout is width-bounded while preserving stored text; truncation is based on Unicode scalars and may split a combining sequence visually. The gate does not establish CJK glyph legibility or complete visual-design parity. A later compact Home/navigation update passed a separate bounded [assessment](control-center-cleanup-assessment-2026-10-14.json), but it does not validate full feature-page UX. This appearance group uses owned virtual targets only. Physical cursor behavior, hardware input, GPU rendering, broader theme layers, and arbitrary application behavior remain outside this scope.

Public workflow references reviewed October 14: [Theme screenshot](https://www.mousemux.com/images/pages/manual/user-theme.png), [Overlay screenshot](https://www.mousemux.com/images/pages/manual/user-overlay.png), and the [manual](https://www.mousemux.com/pages/manual/). Reference copies are research-only in ignored runtime storage, not product assets. Full parity still needs separate plain tag/text/icon layers, offsets/opacity, font face/styles and text colors, visual glyph mirroring, themed application cursor states and GPU rendering. Motion inversion is not visual mirroring, and this text-badge group does not implement an application-icon picker.
