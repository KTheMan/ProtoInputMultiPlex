# Background recovery polling

The [independent bounded assessment](recovery-ui-native-poll-assessment-2026-10-28.json) accepts one current virtual-only recovery workflow.

The GUI reads a cached recovery snapshot. Native process-watch checks run on the session relay, with a 100 ms polling interval checked even while events arrive continuously. Recovery details, Start checks, Stop and close callbacks do not take the mutex used for native process polling. Stop records its intent under the short publication lock; a delayed Running result cannot replace it. Confirmed Stopped and quarantined states retain their existing meanings.

An affected application remains quarantined until its original process exits. A late input release does not grant restart permission. Process handles and enrollment identities remain authoritative; a reused numeric PID is not treated as proof that the original application is safe. The relay retains recovery ownership after worker exit while GUI or agent readers still need it, then releases process watches in the background without a GUI join.

Agent recovery status keeps its existing permission boundary. A sample must come from a real native poll begun after the retained connection/policy ticket and must be no more than two seconds old. Cached status is not assigned a fresh observation time. New controller, recovery or permission generations reset the GUI sampling cursor. Inspect may lack a certifying sample while a fresh one is pending. No tool, grant or input authority is added.
